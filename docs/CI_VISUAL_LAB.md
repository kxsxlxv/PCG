# GitHub Actions Visual Lab — SDK-free

Purpose: let ChatGPT/Codex iterate on a bounded task, inspect actual output, and review visuals without requiring routine user approval or installing UNIGINE. Standard public GitHub hosted Ubuntu CPU runners; no RTX/SDK required. [Runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [billing](https://docs.github.com/en/actions/concepts/billing-and-usage). Public standard runners currently free, private and larger runners subject to account limits/charges. Use ubuntu-24.04, pinned Python 3.11 and direct versions, lock transitive dependencies after smoke. Default job <=15 min, cancel superseded runs, read-only token, no secrets/network imagery/models, no pull_request_target. Use workflow_dispatch plus pull_request (needed by current connector run listing), push to main if desired; don't enable arbitrary fork code on self-hosted workstation. Pin action revisions after verification.
 
L0 bootstrap uses historical stage03/04 actual mesh generators and CPU z-buffer contact sheet, stage06 material/facade PNGs, stage07 CPU test, stage08 scheduler and stage09 coordinate probe; stage05 module JS generator. Not a new production compiler. Outputs to artifact directory; upload even on failure, explicit metric checks; record versions, commit and logs. 
Future Lab separates renderers: CPU depth-buffer (geometry diagnostic, fast, no OpenGL); optional Blender headless Cycles CPU for actual imported GLB/PBR, small scenes fixed 512–1024px, manual lane. [Blender command-line](https://docs.blender.org/manual/en/4.5/advanced/command_line/render.html), [pyrender OSMesa](https://pyrender.readthedocs.io/en/stable/examples/offscreen.html) alternative, not required. No need to build custom PBR renderer. Later optional browser Three.js/WebGL viewer for interactive GLB, not first gate. 
Each CI run: geometry JSON and GLB, architecture GLBs and actual contact sheet, material maps/contact/day/night, per-stage diagnostics, JSON summary. Add top/front/side/iso from loaded exported mesh, per-case fixed cameras, difference images and curated golden review in later tasks. Upload with actions/upload-artifact, retention 14 days; no automatic commit of huge derived assets. GitHub Step Summary links to artifact and metrics; images can be viewed after artifact download. Don't assume relative local PNG links in Step Summary are visible. 
Assistant workflow: create small branch/PR -> pull_request triggers Actions -> connector fetch_commit_workflow_runs (currently PR runs first page only) -> fetch_workflow_run_jobs, job logs -> fetch_workflow_run_artifacts -> download_workflow_artifact returns connector ZIP reference. Actual transfer of ZIP into analysis environment and image inspection must be proven in L0; tool availability does not guarantee extraction access. Alternative: user downloads and attaches ZIP or PNG. Direct workflow_dispatch action not exposed by current connector; use PR trigger or user Run workflow button; rerun existing failed/job via exposed tool if permissions permit. Use the configured hourly automation for bounded iterations. Merge into main only after required CI for the current PR head and applicable visual evidence pass; check the merge result, then start the next increment. Do not bypass branch protection. If a required artifact cannot be inspected, report the blocker rather than merge. Never claim screenshot seen if only logs/artifact metadata available.
 
Optional later self-hosted runner on user's machine for SDK/GPU, only trusted private/isolated jobs, user explicitly installs/configures; do not run untrusted public PR code or expose credentials/SDK files. No self-hosted setup required now.
