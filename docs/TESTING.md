# Acceptance strategy

Use deterministic fixtures with explicit seed and source/revision. Fast tests: schema validation, finite vertices/attributes, index range, degenerate faces, expected volume/area and boundary coverage, watertight closed shells (welded semantic topology, not split render vertices), winding, holes, part coverage, coordinate axis and units, stable IDs/order-independent seeds, facade bounds/nonoverlap, material UV/roles, fit anchors, LOD monotonicity + measured silhouette error, tile ownership and cache limits. Invalid/unhandled inputs produce reasoned fallback or reject, never silent missing buildings. Visual modules can overlap intentionally; distinguish from closed-solid requirements. Exact float/PNG hashes only for pinned environment; compare semantic normalized metrics otherwise. Self-intersections, roof topology, true openings, collision and LOD envelope not covered by existing probes: add explicit tests, no claims of acceptance until passed.
Visual QA: fixed camera/lighting/projection/background/scale, actual exported geometry reloaded, front/side/top/iso; compare same camera across LOD, silhouette masks/depth and pixel difference where meaningful; preserve goldens only after review. Contact sheet plus per-fixture PNG, failed case minimized JSON, GLB, diagnostics. CPU rasterizer useful for topology/occlusion, not PBR; optional Blender CPU for actual PBR visual reference. Never compare arbitrary camera auto-fit across versions as proof of improvement. Check missing/blank output. Use visual review as gate, not replace correctness with SSIM. JUnit JSON/summary and artifact names keyed to commit/run. 
Native tests later [G0–G12](../research/09_integration/SDK_ACCEPTANCE.md); cannot mark PASS in ordinary CI. Runtime simulation only algorithmic scheduling evidence. Local-data quality separate from synthetic tests, stratified held-out observations, no training.
