# Research 06 — Procedural PBR materials and building shaders

Date: 2026-11-24 | UNIGINE 2.22 | PCG | Sandworm excluded

Status: documentation and technical design, plus executed NumPy/Pillow procedural texture experiment. No GPU, SDK, Material Maker, Blender, actual compression or shader compilation tests. All generated maps are original synthetic research assets, not calibrated photographs.

## 1. Architecture decision
Use a compact family of shared materials: pcg_facade, pcg_roof, pcg_trim, pcg_glass, pcg_foundation, pcg_far_building. MaterialResolver selects semantic material ID, physical repeat size, palette tint, weathering, window/emission layout from ArchitecturePlan. Keep architecture independent of render path. Use geometry for silhouettes, maps for microdetail, offline facade baking or analytic window grids for distance. No per-building unique material unless unavoidable. Separate opaque, alpha-tested and transparent pipeline states. Minimize shader permutations; precompile hot variants, profile representative flight scenes.

UNIGINE 2.22 specific evidence:
- [Custom Parameters](https://developer.unigine.com/en/docs/2.22/content/materials/custom_parameters/): project-global separate material and surface layouts, scalar float/int/uint only. Material::setCustomParameter*(), setSurfaceRenderCustomParameter*(), setInstanceCustomParameter*() for Mesh Cluster. Mesh Clutter lacks independent per-instance values. IDs are renderer lookup keys, not durable building IDs; surface ID is view/frame scoped, material ID load/session scoped.
- [Quick Start](https://developer.unigine.com/en/docs/2.22/content/materials/custom_parameters/quick_start): documented example is a post effect. Do not assume these values can be read during the original material's deferred geometry pass, before Surface ID buffers exist. Verify direct object-shader access and cost in SDK 09. If unavailable use supported mesh attributes (packed vertex data/UV channel) for unique tile geometry; for instanced modules test engine instance data or a bounded palette of material groups. Never require a new shader/material per building just to change its color.
- [Texture 2D Array node](https://developer.unigine.com/en/docs/latest/content/materials/graph/node_library/textures/texture_2d_array): supports integer layer selection; documentation identifies 2.22. Equal resolution layers, no interpolation across layers. The documented 16-texture limit is not the number of materials or array layers. Verify GPU layer limits, formats, allocation/residency and import.
- [Mesh abstract material](https://developer.unigine.com/en/docs/2.22/code/materials_shaders/abstract_materials/mesh): custom shader hooks, emission, deferred states, specular AA. Prefer material graph for baseline, UUSL hooks only as necessary. Test all passes incl. shadows, native depth, thermal views where applicable.
- [Texture optimization](https://developer.unigine.com/en/docs/2.22/content/optimization/textures/), [textures declaration](https://developer.unigine.com/en/docs/2.22/code/formats/materials_formats/ulon_materials/textures), [user material format](https://developer.unigine.com/en/docs/2.22/code/formats/materials_formats/user_material_format).

## 2. PBR schema and material factory
Canonical source maps: base color sRGB; normal tangent space linear (explicit +Y/OpenGL convention, verify target flip); ORM linear R=AO G=roughness B=metalness; optional height normalized plus physical amplitude in meters; optional emissive in linear radiance representation or sRGB encoded color map with linear factor. glTF conventions reference [spec](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html). UNIGINE mesh_base shading texture packing differs from glTF ORM: do NOT copy blindly, verify target version and repack or read explicitly in custom material. AO only indirect contribution, not multiply all direct illumination; don't bake sun/shadows into base color. Painted metal is dielectric coating (metalness 0), exposed metal 1; corrosion separate; plaster/concrete/brick/ceramic/bitumen dielectric. Roughness and colors initially proposals, not measured. 8-bit height in probe is diagnostic; use 16-bit source where relief precision matters.
MaterialRecipe fields: stable id/revision, family, physical tile extent, base color space, channel semantics, normal convention, height amplitude, seed, graph/source provenance and license, texture resolution, mip algorithm, compression, palette eligibility, allowed roof/facade roles. Cache key includes full recipe, backend and tool versions. Export PNG/EXR sources; compression as separate target adapter. All repeated patterns aligned to real-world scale. For sloped roofs UV0 in slope-plane basis from geometry 03, grain along drainage direction. Keep same roof tint and mean appearance across all LOD.

Tools:
- [Material Maker](https://github.com/RodZill4/material-maker), [CLI](https://rodzill4.github.io/material-maker/doc/command_line.html), [export](https://rodzill4.github.io/material-maker/doc/export.html): graph-based procedural PBR; documented batch CLI is material_maker --export-material --target Blender -o output input.ptex. CLI may require real rendering context; verify exact pinned executable, exporter resolution and output naming, timeout/error handling. [Custom target](https://github.com/RodZill4/material-maker/wiki/FAQ/8580f153cc52caaf18b1657589d23021ca099b0). Agent-oriented tools [codex-material-maker](https://github.com/xrowex/codex-material-maker) and [Tool-MaterialMaker-MCP](https://github.com/graysonchalmers/Tool-MaterialMaker-MCP) are candidates only; inspect source, compatibility and licenses before use, not dependencies.
- [MaterialX](https://github.com/AcademySoftwareFoundation/MaterialX), [TextureBaker](https://github.com/AcademySoftwareFoundation/MaterialX/blob/main/python/Scripts/baketextures.py): portable graph exchange and baking candidate, not native UNIGINE graph compatibility. [TextureLab](https://texturelab.io/) alternative; Blender shader graphs/Cycles and direct NumPy for tests.
- [ambientCG](https://ambientcg.com/), [Poly Haven](https://polyhaven.com/) CC0 reference PBR materials; API terms separately; record source ID, file hashes, physical scale and licenses. Do not publish external maps unless allowed. Variants are palette/roughness/scale/aging profiles, not copies of every map. Calibrate region using reference images at research 07.

## 3. Arrays, atlases and memory
Prefer arrays grouped by map type/resolution/color space/compression: all layers identical dimensions and format, consistent layer indices across albedo/normal/ORM. Separate wall/roof arrays or banks where residency matters. Array is not virtual texturing: a large bank can remain fully allocated; verify native streaming. Atlas for trims and baked facades: preserve gutters at every mip, avoid sampling neighboring islands, generate mip levels per tile before packing where possible. Do not use fract UV without gradients; sample with gradients from unwrapped coordinates or native repeat for arrays. Avoid mip bleeding and anisotropic cross-island filtering. No arbitrary runtime selection via bindless assumptions.
BC1/BC4 = 8 bytes per 4x4 block, BC5/BC7 = 16. [Microsoft block compression](https://learn.microsoft.com/en-us/windows/win32/direct3d11/texture-block-compression-in-direct3d-11). Candidate BC7 albedo sRGB, BC5 normal XY (reconstruct +Z, renormalize), BC7 or BC1 ORM (compare cross-channel artifacts), optional BC4 height. [KTX Software](https://github.com/KhronosGroup/KTX-Software), [DirectXTex](https://github.com/microsoft/DirectXTex), [BasisU glTF extension](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_texture_basisu). BasisU file size is not final GPU residency; glTF BasisU extension targets 2D images, not custom arrays. Confirm engine formats/import.
Exact block payload for square n full mips = sum over mip dimensions max(1,ceil(w/4))*max(1,ceil(h/4))*blockbytes. For 32 layers, 3 BC16 maps: 512=32.0024 MiB; 1024=128.0024 MiB; 2048=512.0024 MiB; 4096=2048.0024 MiB. With BC4 height: 37.3362/149.3362/597.3362/2389.3362 MiB. Excludes allocator padding, residency, staging, CPU copy, descriptor and render targets. Actual compression not performed. Start with 512-1024 for most tiling maps, higher only with measured visual gain. Example 12 walls+10 roofs at 1024 plus 13 trims/plinths at 512 gives approx 101 MiB for these three maps; glass/interior banks extra. Budget subject to stage 08/09.

## 4. Repetition and weathering
Use stable region/complex/building/surface/window seeds. Variation hierarchy: base pattern -> palette tint -> macro modulation -> localized masks. For isotropic plaster/concrete candidate stochastic hex tiling [Mikkelsen 2022](https://jcgt.org/published/0011/03/05/), histogram-preserving synthesis [Heitz/Neyret](https://eheitzresearch.wordpress.com/722-2/) and [Burley](https://jcgt.org/published/0008/04/02/). Hex tiling typically needs multiple samples per map; compare 3-map baseline vs three neighboring samples per map, not same cost. Use matched random transforms across albedo/normal/ORM; transform normal XY consistently. No arbitrary rotation of directional brick courses, sheet-metal ribs, tile rows. Maintain facade seam phase across corners where architecture requires. For directional textures use structured per-element hue variation and long-period offsets, not rotating pattern.
Weathering masks: base contact dirt by height above foundation, drip streaks beneath sill/eave, protected zones under balcony/overhang, facade orientation and rain exposure, roof slope/drainage direction, stable noise. Do not use per-pixel expensive ray queries. Geometry compiler provides semantic masks/distances; bake or atlas where possible. Wetness changes roughness and color without turning plaster metallic. Avoid global high-frequency grunge; maintenance era is profile-dependent.
Mip generation: linear-space albedo averaging (encode sRGB after filtering); normal vectors average then normalize but retain variance for specular AA or evaluate engine support; roughness filtering based on BRDF, not arbitrary average; emissive average in linear light. [LEAN Mapping](https://userpages.cs.umbc.edu/olano/papers/lean/) and [Toksvig discussion](https://blog.selfshadow.com/2011/07/22/specular-showdown/). Use analytic AA/fwidth for procedural grid transitions; use explicit derivatives before discontinuous UV operations, sampleGrad where required. Prevent shimmer at high oblique flight angles.

## 5. Facade rendering and interior mapping
Geometry compiler emits metric facade UV, semantic section/floor IDs and plan (window/balcony layout, masks). Prefer near actual frames and recess geometry; mid opaque facade shader or baked slots, preserve balconies as silhouette geometry; far compact facade proxy with mip-filtered window coverage and emissive. Irregular layouts use baked/reusable facade panels or a compact layout buffer; do not assume one repeated grid represents all architecture. Do not use fullscreen per-window loops.
Interior Mapping [van Dongen, CGI 2008](https://www.proun-game.com/Oogst3D/CODING/InteriorMapping/InteriorMapping.pdf), [Humus cubemap implementation](https://humus.name/index.php?ID=80&page=3D): ray-box intersection into a virtual room from window plane in local room coordinates. For ray origin p inside/on box, direction d pointing inwards, tExit=min over axes of distance to exit plane / direction component (parallel axes infinite). Select hit plane and texture coordinates or sample cubemap with hit point relative to room center; valid only inside window mask. Avoid division by zero, clamp near boundary, no camera-ray-dependent random seed, handle backfaces. Physical width/height/depth and window ID consistent with facade plan. Composite interior behind reflection/tint; opaque proxy avoids mass transparency sorting. Glass F0 approx 0.04 for IOR 1.5; Schlick Fresnel blends reflection and transmission proxy. Test actual engine lighting/reflections and color spaces; no double lighting of prelit room textures. Interior mapping is visual illusion only (no physical depth, collisions, shadows or accurate reflections). POM adds repeated texture fetches and grazing-angle artifacts; reserve for close areas, not every roof/wall. Don't fake balconies and major roof ridges with POM. Disable interior/POM when projected window/relief small; fade to prefiltered proxy. Proposed initial thresholds >32 px near, 8-32 px mid, <8 px baked; profile and use hysteresis, not hard fixed distance.

## 6. Night lighting
Stable per-window semantic ID and seed. Use occupancy probability by building type, floor, local time; independent of frame/tile order/LOD. Avoid random flashing; optional state transition over minutes, stable schedule with crossfade. Use global sun/time factor, local emissive intensity and varied warm/neutral colors, curtains as masks. No actual point light per window; reserve real local lights for selected near locations. Emissive is HDR linear contribution in engine; tune exposure/bloom with flight scene. Far night LOD preserves aggregate emitting area/energy; do not threshold averaged emissive mips or rehash by camera distance. If changing occupancy at runtime, far facade needs matching aggregation or coherent approximation. Avoid pixel-perfect grid aliasing via analytic coverage or baked mips. Thermal response is separate simulation quantity, not visible emission.

## 7. Executed experiment
[material_probe.py](06_materials/material_probe.py), Python 3, NumPy 2.3.5, Pillow 12.3.0. Run:
    pip install numpy pillow
    python research/06_materials/material_probe.py --output generated_materials --size 512

8 materials x 4 maps = 32 original 512² PNG maps: cream/white plaster, red brick, concrete, stone plinth, painted red profiled metal, ceramic roof, bitumen. Periodic value noise and modular patterns; metric normal calculated by wrapped finite differences of normalized height times amplitude. Source maps and preview PNGs generated locally, not committed to public repo; regenerate with code. PNG maps total 6,853,716 bytes on test environment, NOT GPU bytes. All maps finite, in [0,1], same array on repeated generation and exact PNG readback of quantized pixels. Pre-quantization normal max length error 2.22e-16 each. Seam step ratio (height map mean cross-edge neighbor step / mean interior neighbor step, Y/X) ranges 0.125–1.0275; diagnostic only, not proof of seamlessness for all maps or mip levels. Patterns visibly too regular; noise/detail calibration and photographic QA still required.
Illustrative 960x384 facade with 48 window slots, 21 lit (one deterministic sample at p=.32, observed fraction 43.75%, not target population fraction). Repeated generation returned identical records. 8x8 box filter on linear emissive preserves channel mean to max error 3.85e-15. This proves arithmetic conservation in float reference, not real GPU filtering, HDR exposure or final night quality. Preview is orthographic illustration and simple diffuse material swatches, not a PBR renderer. Normal orientation, height quantization, mip chain, material pack and GPU results require engine tests. ## 8. Codex implementation / acceptance
1. Define MaterialRecipe + texture manifests and explicit color/channel conventions; create pinned offline workers (procedural direct generator and Material Maker).
2. Build measured regional palettes and physically scaled wall/roof/trim materials. Add actual texture compression and mip-aware QA; compare BC1 vs BC7 ORM errors.
3. Implement array/atlas importer and simple opaque baseline in UNIGINE, assert layer correctness, color space, normal orientation, target channel packing and stable IDs.
4. Test per-instance customization during correct render pass and draw calls; fallback to packed mesh attributes / bounded material groups. Test Mesh Cluster vs static tile mesh.
5. Implement semantic facade grid, opaque glass proxy and emissive; compare geometry vs facade masks and far bake using same ArchitecturePlan.
6. Add weathering and optional stochastic sampling/interior mapping as separate feature switches. Compare GPU frame time, shader sampling/occupancy, shader permutations, VRAM and visual quality at flight angles; disable expensive feature when not visible.
7. Test day/night, high speed camera, low sun, rainy conditions, 1080p/1440p/2160p, several altitudes; validate mip/LOD transitions, streaming and no window flicker. Actual budgets determined in 08/09.
8. Next study 07: CV/AI for roof color/shape, facades, material inference, confidence and validation.

Decisions about material counts, resolution, roughness, LOD thresholds and shading families are preliminary engineering choices. No SDK compilation, no actual compression, no Material Maker execution or AI inference, no real Adler image analysis. Never label prototype textures photorealistic.
