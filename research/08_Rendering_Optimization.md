# Research 08 — Rendering optimization and streaming

Date: 2026-11-25 | PCG | UNIGINE 2.22 | desktop RTX 5070 Ti (16 GB GDDR7)
Status: engine documentation/API audit, executable synthetic scheduling and LOD model; no native SDK or GPU measurements. No runtime AI, no Sandworm.

## 1. Decision: spatially batched hybrid, not one node per building
Compile unique wall/roof/foundation shells into spatially bounded indexed meshes grouped by material/pipeline/LOD. Use ObjectMeshCluster for genuinely identical reusable assets (windows, railings, HVAC, small repeated roof equipment, possibly entire identical houses). Keep per-instance transform and variation data separate, shared geometry and texture banks global. Use mid/distant facade masks or baked panels instead of thousands of window instances. Near collisions and query metadata separate from render meshes. Don't create individual Node, material instance, light or physics body per window. Don't combine the whole city into one mesh: culling, LOD, rebuild and streaming granularity would be lost. Don't assume a cluster is one draw call: material surfaces, internal splits and passes still matter.

Initial comparison: individual ObjectMeshStatic (baseline), spatially merged ObjectMeshStatic, MeshCluster of shared mesh, hybrid. Try subcells 128/256 m inside 512 m storage tile; 1024/2048 m parents. Group by (spatial subcell, geometry asset, material state, LOD, shadow policy), cap batch bounds and vertex/index limits. Merge small unique shells per group, keep optional building ID → index range/semantic metadata sidecar. At close range use tighter bounds; distant parent tiles can use larger bounds. Choose cell size by measured density, draw calls and overdraw, not a universal constant. Avoid global clusters of every window type; spatial locality remains important.

## 2. Native UNIGINE evidence
Versioned documentation and public ai-docs source, not compiled or linked against SDK:

- [ObjectMeshCluster API](https://developer.unigine.com/en/docs/2.22/api/library/objects/class.objectmeshcluster), [C++ API source](https://github.com/unigine-engine/ai-docs/blob/main/ai_docs/md_docs/api/library/objects/class.objectmeshcluster_cpp.md): addMeshTransform(), setMeshTransform(), setMeshPath(), getMeshCurrentVRAM(), getMeshAsyncVRAM(), getMeshDynamicVRAM(). Documentation explicitly marks VRAM load requests as main-thread calls; DynamicVRAM is documented for custom prefetch but can force-load if async mode disabled. Don't invoke it indiscriminately in worker threads. Test exact signatures and actual readiness/lifetime on SDK 2.22, including disabled nodes, unload and cache.
- [LOD setup](https://developer.unigine.com/en/docs/2.22/content/optimization/geometry/lods/), [world management](https://developer.unigine.com/en/docs/2.22/principles/world_management/): native surface visibility/fade distances, reference parent bounds; importer auto-LOD uses meshoptimizer. For synchronized representation use shared reference bounds; independent surface bounds can cause overlap and z-fighting. Use authored semantic LOD before importer decimation.
- [Asynchronous streaming](https://developer.unigine.com/en/docs/2.22/principles/data_streaming/), [streaming settings](https://developer.unigine.com/en/docs/2.22/editor2/settings/render_settings/streaming/): resource loads/upload in async threads, scene synchronization on CPU; separate CPU/GPU mesh and texture modes, budgets, cache and mip streaming. Async shader compilation can cause not-ready objects; Force can freeze. Engine resource streaming is not a world-level spatial tile scheduler. Engine documented VRAM usage limit default 80%, free space default 512 MB, overcommit off. Keep driver budget/reserve, don't blindly allocate full VRAM or turn overcommit on.
- [Culling](https://developer.unigine.com/en/docs/2.22/content/optimization/geometry/culling/), [Occluder Mesh](https://developer.unigine.com/en/docs/latest/objects/worlds/world_occluders/occluder_mesh/): native occlusion and frustum support, queries on bounds; test flags/latency and savings. Do not use synchronous per-object GPU readback. At high altitude occlusion savings may be weak, query overhead may dominate.
- [Custom Parameters](https://developer.unigine.com/en/docs/2.22/content/materials/custom_parameters/), stage 06: per-instance MeshCluster values documented; verify visibility in actual geometry pass, not just post-process. Fallback bounded palette or packed vertex attributes for unique geometry.
- [Profiler dumps](https://developer.unigine.com/en/docs/2.22/tools/profiling/profiler_dump/index), [performance profiler](https://developer.unigine.com/en/docs/2.21/tools/profiling/profiler/), [lights optimization](https://developer.unigine.com/en/docs/latest/content/optimization/lights/): measure CPU/GPU, passes, allocations and streaming. Profile release runtime outside editor. Native screenshots/profiler dumps needed in stage 09/implementation.
- [meshoptimizer](https://github.com/zeux/meshoptimizer), [3D Tiles spec](https://github.com/CesiumGS/3d-tiles/blob/main/specification/README.adoc): offline vertex cache/fetch optimization, simplification with attributes, meshlet generation (optional; no evidence PCG can submit custom mesh shaders via UNIGINE), hierarchical geometric error and replacement semantics. Adopt concepts, not require Cesium or 3D Tiles plugin.

## 3. Semantic LOD and HLOD
LOD0 detailed apertures/frames/rails; LOD1 main silhouettes and roofs with simplified modular details; LOD2 shell with roof forms, facade masks/baked windows and larger balconies; LOD3 coarse block shell preserving footprint, roof color and major slopes where visible; HLOD parent aggregates across several tiles. Never randomly replace all roofs with flat surfaces. Landmark exception/importance. Initial illustrative triangles per average building: 1800/360/80/24; variable with building size/complexity, not hard limits or actual measured content. Projected error e_px ~= epsilon_m * H/(2*tan(verticalFOV/2)*d); use conservative closest view-depth/bounds for real culling, not camera altitude or center Euclidean distance alone. Formula approximation invalid near camera/near plane; force finer representation. Error includes roof silhouette, protrusions and height; store measured world-space bound or explicitly approximate bound, monotonically nondecreasing parent error, not triangle count as error. For 1440 px vertical 60 deg, 1.5 px threshold, errors .12/.65/2.5 m imply distances about 100/540/2078 m. Change with FOV/resolution (including zoom and sensor views); native distance thresholds may need presets or separate manager. Material LOD must preserve palette/mean linear emission. Hysteresis refine >1.8 px, coarsen <1.2 px (example); minimum residency and fade window. Crossfade has temporary double draw/residency and potential shadow artifacts; prefer bounded dither if engine supports it, otherwise synchronized switch with error control.
HLOD replacement: parent covers exactly owned descendants, keep visible parent until all required children are GPU+shader ready, atomic replace in render update. For partial refinement partition parent coverage explicitly, never draw overlapping parent/child building sets. Keep fallback until children ready; coarsen in reverse. Do not evict required coverage or last fallback. Memory reservation includes both representations during transition. Shared asset refs counted across tiles. Far city silhouettes are geometry, not camera-facing billboards for entire district. Impostors optional for distant landmark after measured image errors.

## 4. Tile format and runtime
Offline quadtree/sparse hierarchy with fixed grid origin and deterministic ownership by representative point (not centroid if outside polygon); building and all attached modules owned by one leaf, no clipping at tile boundaries. Expand actual content bounds to include protrusions, overhang and all parts. Large structures may have dedicated tile/resource. Spatial indices must use content AABB, not ownership grid alone. Parent content generated from same IDs. Tile metadata: tile_id/revision, CRS, double origin/ENU or local projected frame, bounding volume, children, geometric error, coverage IDs, resource IDs/checksums, compressed and decoded bytes, estimated GPU bytes, triangle/surface/instance counts, dependency list, shadow/collision proxies. Double world transform, float local vertices. Tile size initially 512m leaf, 128/256m batch, parents 1024/2048/4096m; vary with density. Keep manifest/index small and loaded separately, no node per unloaded tile. Pack many small records for I/O locality, versioned content-addressed chunks; engine-native meshes or precompiled resources for production, glTF interchange only. No repeated JSON/glTF parse during flight.

State machine: Absent -> Requested -> Reading -> Decoded -> QueuedUpload -> ResourceReady -> Active -> Retiring -> Cached/Absent; Failure -> backoff/fallback. Request generation token prevents late completions from reviving evicted tiles; cancellation cooperative; workers only file reads/decompression/CPU data prep; bounded queues; main-thread node/API activation, documented upload request affinity, actual async engine GPU stage. Ready means renderable (mesh, material, textures sufficient mip, shader ready), not just decoded. Retire after replacement active, fence/lifetime rules per SDK. Pin ancestors and active resources; cache eviction by recency, distance/time-to-use, size and rebuild cost. Admission checks reserve RAM/VRAM/staging/overlap, never unbounded futures. Bounded activation per frame and dynamic quality under pressure. Camera teleport/rapid turn: immediately request coarse coverage, cancel stale detail, keep fallback, rebuild predictor. No whole-world preloading beyond measured small pilot.
Prediction: trajectory corridor based on aircraft velocity and turn rate plus camera/gaze frustum (not aircraft heading alone), 2–5 s initial lookahead, priority current uncovered coarse > current required refinement > soon-visible coarse > soon-visible refinement > cache warm. Time-to-need minus estimated end-to-end latency plus error/importance/cost. Use p95 latency and bandwidth EMA with guard bands; predicted sweep plus side reserve. Avoid blocking current demand with speculative work. At v=250m/s and 3s horizon, 750m forward margin; for 512m tiles, roughly 1.5 tile widths, not entire circle in all directions. For circular demand radius R, planar strip arrival area ~2Rv, tile count rate ~2Rv/L^2; actual discrete grid bursts, turning and service latency matter. If service demand exceeds capacity, prefetch alone cannot solve it: increase SSE threshold, choose cheaper representation, reduce detail radius, defer shadows/secondary assets and cap queue. Maintain coarse coverage before detail.

## 5. Culling, shadows and material cost
CPU traverse hierarchy with camera frustum and bounds, conservatively expand for shadow caster volume; include relevant off-screen casters, reflections and additional views separately. No assumption visible geometry equals submitted geometry or total triangles across passes. Use engine frustum and optional hardware occlusion on nodes/clusters after broadphase. At ground level urban occlusion likely helps; from air many roofs visible. Benchmark occlusion on/off, never use a non-conservative occluder that hides actual buildings. Occluder proxy from opaque major solids, not thin balconies/transparent windows; avoid whole giant occluder across holes. Shadow LOD separately: near silhouette and major balcony masses; mid simple shell/roof; far reduced shadow distance or none, preserve low-sun coherence. Shadow cascades multiply geometry work; no tiny railing/AC shadows in every cascade. Use world sunlight; emissive windows rather than point lights. Test shadow distance/size/count, caster vs receiver and shadow proxy material support; no baked directional sunlight in albedo. Material families 06: opaque shared banks, keep transparency exceptional; avoid expensive POM/interior mapping and stochastic tiling on small projected surfaces; track overdraw, bandwidth and shader passes. TAA/upscaling settings explicit; frame generation not substitute for real frame time.

## 6. Initial budgets, NOT measured capacities
Target desktop RTX 5070 Ti 16 GB (NVIDIA spec https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5070-family/). CPU/RAM/disk/resolution not supplied. Proposed baseline 2560x1440, 60 real FPS (16.67 ms), full terrain/cloud/vegetation scene, fixed render settings. PCG incremental GPU <=4 ms p95, CPU main-thread <=2 ms p95 including streaming activation <=0.75 ms; CPU and GPU overlap, not simply additive. Overall p95 <=16.67 ms, p99 <=25 ms stretch goal; validate with baseline scene and repeat runs. VRAM soft PCG cap 2 GiB, hard provisional 3 GiB including tile meshes, instance buffers, shared texture arrays, staging and transition overlap. Target total process VRAM below driver budget with ~2 GiB free headroom when possible; don't interpret 16 GB as available to PCG. Example allocation PCG: 0.6 GiB geometry+instances, 0.4 GiB shared textures, 0.4 GiB far atlases, 0.6 GiB transient/cache; actual engine resource counters decide. Adapt if terrain/render targets consume more. CPU cache initial 1–2 GiB only if physical RAM allows; reserve OS/engine. No disk assumption; measure SSD and decode/upload rate. Start visible candidate triangle envelope 1–2M main-pass geometry, not a hardware capability or guaranteed performance; count draw calls/surfaces, passes and p99. Estimate index/vertex payload from actual exported counts and stride (e.g. 32 B vertex and 6/12 B indices per triangle), not triangles alone. Shared textures 06 memory model separate; native resource allocation can differ.
