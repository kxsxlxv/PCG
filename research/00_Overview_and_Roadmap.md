# 00 — Initial technology survey and research roadmap

Дата: 2026-11-24. Проект PCG (рабочее название GeoWorld PCG). Целевая платформа UNIGINE 2.22; пилотный регион — Сочи / Адлер.

## Исходная постановка и решения пользователя

Нужен независимый генератор зданий реальной местности для авиасимулятора с визуальной целью уровня Microsoft Flight Simulator, X-Plane и War Thunder. Требуется масштабирование на большие территории, эффективный рендеринг, правдоподобная региональная архитектура. Sandworm полностью исключён: закрытый код не позволяет контролировать и расширять алгоритмы. Использовать доступные открытые проекты и библиотеки, не создавать заново уже решённые задачи. Проект пока исследовательский личный тест, а не production. Наличие 3D-художника не предполагается: модели, архитектурные детали, материалы, UV и LOD должны производиться программно. Условия доступа и лицензии сохранять в provenance, особенно перед публичным распространением кода или данных; некоммерческий тест сам по себе не разрешает произвольную публикацию чужих ресурсов.

## Изученные подходы к генерации миров

- MSFS: Blackshark.ai — глобальная реконструкция по геоданным, машинное распознавание и синтез архитектурных объёмов. Публичные сведения не раскрывают закрытые алгоритмы. https://blackshark.ai/
- X-Plane: автогенерация через классы застройки, библиотечные OBJ, процедурные FAC, AGP/AGS, DSF. SimHeaven X-WORLD объединяет OSM и дополнительные контуры; полезный пример разделения данных и визуальных библиотек. https://simheaven.com/ ; https://github.com/d41k4n/world-models
- FlightGear: osm2city — непосредственный открытый референс авиационного генератора: GIS, эвристики, крыши, фасадные текстуры, ночное освещение. https://gitlab.com/osm2city/osm2city/ ; https://osm2city.readthedocs.io/en/latest/
- War Thunder / Dagor: открытый движок интересен подходами к статической геометрии, инстансингу и компиляции мира. Публичного подтверждения идентичного глобального генератора реальной застройки нет. https://github.com/GaijinEntertainment/DagorEngine
- Другие игры: Arma GameRealisticMap — независимые GIS-конвейеры и подбор моделей; Arnis (Minecraft), GeoSkylines и rsgeotools — дополнительные примеры. https://github.com/jetelain/ArmaRealMap ; https://github.com/louis-e/arnis ; https://www.mdpi.com/2220-9964/9/1/17 ; https://github.com/romanshuvalov/rsgeotools

## Предварительная архитектура

1. GIS Acquisition: OSM PBF, Overture, Microsoft, GBA, DTM/DSM, жилищные реестры, опционально снимки.
2. Data Fusion: нормализация, идентификация, соответствия 1:1 и 1:N, provenance каждого атрибута.
3. BuildingDescriptor: контур и части, высота, этажность, крыша, назначение, архитектура, материалы, confidence, стабильный ID.
4. Architecture Engine: классификация, региональные профили, Shape Grammar, семантический ArchitecturePlan.
5. Geometry Engine: repair, triangulation, massing, roofs, foundations, semantic surfaces and edges.
6. Procedural Asset Factory: Blender/Python/BMesh, параметрические окна, балконы, двери, кровельные детали; автоматический UV, baking, PBR, LOD и QA.
7. Material Compiler: общие физически масштабированные PBR-материалы, trim sheets/atlas/arrays при подтверждённой поддержке SDK, процедурная вариативность, ночные окна.
8. World Compiler: семантические LOD, meshoptimizer, инстансируемые модули, тайлы, HLOD, пространственный индекс.
9. UNIGINE Adapter & Runtime: собственный экспорт, нативные меши, материалы, стриминг, culling, геопривязка, измерения CPU/GPU. Нативные механизмы движка допустимы, Sandworm исключён полностью.

Главная идея: гибрид уникальной геометрии по реальному контуру и инстансируемых деталей, офлайн-компиляция, компактное runtime-представление. Не использовать одну уникальную текстуру на каждый дом. Не требовать Blender или GIS-библиотеки в runtime.

## Качество и производительность

Целевые LOD должны строиться из одной семантической модели: ближние — реальные объёмные архитектурные детали, средние — упрощённые детали/текстуры, дальние — сохранение силуэта и скатов, HLOD — объединение группы зданий. Проектные стартовые бюджеты из первого обзора (не измеренные): LOD0 500–2500 треугольников для простого дома, LOD1 100–500, LOD2 24–150, LOD3 12–50; крупные здания требуют других бюджетов. Привязать переключение к screen-space error, использовать hysteresis. Начальные размеры тайлов для эксперимента 256/512/1024/2048 м. Оценить предиктивный стриминг по движению камеры/самолёта, memory budgets, стабильные ID на границах тайлов. Обязательно сравнить уникальные меши, archetype instancing и гибридный pipeline. Никаких заявлений о достигнутом FPS без реального теста SDK.

Пилотные сцены: центральный Адлер, частный сектор, многоэтажная застройка, Имеретинская низменность, склоны Хосты. Проверять на дистанциях порядка 2, 50, 300, 1500 и 5000 м, в дневном/ночном освещении, при высокоскоростном пролёте. Метрики: CPU/GPU frame time, P95/P99, draw calls, VRAM, triangles, shadow pass, IO throughput, pop-in, height MAE, roof class accuracy, footprint IoU. Точные пороги TBD.

## Research roadmap

| Номер | Тема | Статус на 2026-11-24 |
|---|---|---|
| 00 | Общий обзор технологий, план | Исследовано |
| 01 | Геоданные, Data Fusion | Документация и прототип аудита; реальный локальный аудит впереди |
| 02 | Open Source code audit | Исследовано по доступному коду и документации |
| 03 | Вычислительная геометрия | Документация, синтетические эксперименты; CGAL ещё не протестирован |
| 04 | Architecture Intelligence / ADL | Документация, прототип фасадов и профилей |
| 05 | Procedural Asset Factory | Следующий этап |
| 06 | Материалы, текстуры, шейдеры | Запланировано |
| 07 | Computer Vision / AI | Запланировано |
| 08 | Rendering optimization | Запланировано |
| 09 | UNIGINE 2.22 SDK | Запланировано |
| 10 | Финальная архитектура и ТЗ Codex | Запланировано |

Порядок фактического исследования: 00 → 02 → 01 → 03 → 04. Следующие этапы продолжаются по нумерации. Предварительные результаты не являются обязательными архитектурными решениями до проверки локальными экспериментами. Не начинать массовое производство зданий до проверки основных ограничений геометрии, качества архитектурных модулей, GPU-представления и API UNIGINE.
