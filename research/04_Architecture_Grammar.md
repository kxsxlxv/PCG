# GeoWorld PCG — Research 04: Architectural intelligence and grammar

Date: 2026-11-24. Target: UNIGINE 2.22, offline independent compiler; no Sandworm; no required manual artist. This is a research specification, not a production implementation. All numeric profile defaults are illustrative priors, not measurements of Adler buildings.

## Decision
Use a typed, declarative architecture profile format (JSON initially, YAML optional), compile it into a semantic facade/layout IR, and use a hybrid of hierarchical massing, split/repeat, layered facade grids and constraint resolution. Do not build a general-purpose CGA parser or depend on a proprietary procedural engine in the MVP. Architectural decisions are resolved once, before rendering LODs are emitted. Keep grammar and geometry backends separate. The facade prototype is a narrow experiment, not the proposed full ADL interpreter.

## Semantic data contracts
`ArchitectureProfile`: version, ID, parent, applicability, regional/epoch priors, floor bands, span/pitch constraints, facade layers, roof request, material requirements, module references, renovation distributions, fallback and LOD policies. Explicit inheritance merge: replace arrays, merge maps by named field, no cycles, stable IDs. Validate units, probability domain, references, budgets and version. No arbitrary eval; typed operation registry and expression AST if needed. JSON schema recommended.

`ResolvedArchitecture`: source building/part IDs, footprint geometry reference, resolved height and floor levels, profile, confidence/provenance, seed version, palette, roof request, section layout, ground entrances. Never overwrite known facts silently. Keep observations separate from synthetic choices. Height solve: H_total = H_min + H_body + H_roof (consistent reference convention); distribute floor heights subject to min/max and hard known count; if infeasible flag conflict and preserve trusted envelope. Separate parapet and technical appendage height semantics.

`FacadeSurface`: surface ID, adjacent part IDs, role, local 2D polygon including holes, world transform, outward normal, elevation range, party wall status, exposure/road direction, floor-line reference, edge IDs. Consume stage 03 Semantic Geometry; never replace footprint with bounding box just to fit a grammar. Use clipping and openings entirely contained within local surface. Match collinear neighboring fragments into logical facade when appropriate, without losing part topology.

`FacadeLayout`: stable wall, floor, section and bay IDs, opening polygons, anchor points, module intents, material masks, occlusion constraints, explicit fallback diagnostics. Separate structural grid, openings (exclusive occupancy), balcony assemblies, decoration, materials/aging. Shared grid aligns floor levels and vertical stacks; no independent random windows. Blank party walls and masked neighboring obstructions. Street-facing side via distance, facade orientation, parcel access and POI; not simply nearest road. Roof decorations use semantic surface/edge requests.

`RenderPlan`: shell surface list; shared asset references + transforms/material parameter IDs; facade mask/UV instructions; geometry LOD recipes, shadow and collision proxy. Generated from the same resolved layout for all LODs. Maintain stable emissive window ID. Rendering backend should not reroll architecture.

## Layout solver
For wall length L, corner margins ml,mr, available A=L-ml-mr, bay bounds bmin,bmax: enumerate n in [ceil(A/bmax), floor(A/bmin)] with n>=1; choose nearest preferred width A/n to btarget. If no valid n, use a declared fallback (blank narrow wall, end panel or alternate module); never squeeze an opening outside its bay. For known entrances/sections solve their number/width first, then bay grids within sections. Window must fit in bay and floor with jamb/head/sill clearance. Balcony requires accessible balcony door or combined module, support and clearance; don't apply residential balcony on industrial profile. Decoration must not occlude opening except explicitly allowed frame/shutter etc. Detect corner collisions, neighbor obstructions and party walls using spatial index; handle gable clipping. Use finite enumeration/dynamic programming for repetitive grids; CP-SAT optional for nonuniform sections, symmetry, reserved intervals or mixed module widths. Use integer millimetres and bounded runtime, report timeout/infeasible separately. Do not use optimizer to override reliable measured geometry.

Randomness: stable canonical hash(world_seed, building_id, profile_revision, semantic_path, property_id), explicit scoped seed policy. Do not use Python hash() or traversal order. Profile updates may deliberately change appearance; version seeds and allow compatibility. Reuse decisions in every LOD and incremental rebuild. Correlation: regional prior, neighborhood, known building complex, building, stack, per-opening. Assign group only from evidence or confidence; avoid smoothing across unlike neighbors.

## Classification
Rule baseline: reliable explicit use/type/series/height first, then probabilistic candidates with geometry and context. Features: area, compactness 4*pi*A/P^2, OBB aspect and fill, number of parts, height/floors, era, structural material, POI/landuse, road exposure, slope, nearby class frequencies. Optional CatBoost on manually audited examples, spatial group holdout to prevent leakage, confusion matrix, macro F1, per-class recall, calibration/Brier score, abstention. Exact series matching must be high confidence and verified. No training or local statistical distribution established. Suggested 300–500 labeled diverse buildings initially, later expand; do not present this as sufficient for a reliable ML model without learning curves.

## Experiment (executed)
See architecture_research/architecture_probe.py, blacksea_profiles.json, geometry_probe.py (copied from stage 03), architecture_probe_results.json, two GLBs and contact PNG. 6 profiles, 200 random rectangle cases each, 1,200 total. 0 logical aperture bounds/overlap/balcony-floor violations; 0 repeated-call mismatches; 274 of 4,800 faces have no feasible bays and intentionally remain blank (includes narrow synthetic sides). This is not full geometric collision validation and not a test across changed evaluation orders. 18 sample models: 1,344 regular windows, 596 balcony-door slots, 18 entrances. LOD0 proxy total 103,230 triangles, LOD1 proxy 25,398 triangles (~75.4% reduction). GLBs exported and read back as 18 geometries each. Preview rendered using CPU orthographic depth buffer from actual triangles. LOD1 still contains geometric opening proxies, no texture bake; no PBR, real cutouts, occlusion, group classification, variable-height solver, actual arbitrary-footprint grammar or production constraints. Both proxy LODs share same layout. No benchmark in UNIGINE. Rectangular sample massing, generic panel class not actual 1-335AS series. Visual inspection indicates regular grids, distinct silhouettes, but repetitive facade styling and primitive box balconies; next stage must improve modules and proportions, add roof-specific assets and material depth. Fixed 30-degree sloped roof inherited from geometry probe unsuitable for many industrial roofs; expose pitch in production. No exact dimensions derived from photographs. Ground base bands split at door in probe, balcony door proxies added, no structural validation.

Run from architecture_research directory: `python -m pip install 'shapely>=2.1,<3' numpy trimesh matplotlib`; `python architecture_probe.py`. It writes JSON, GLB and PNG; offline after deps installed. GLB is Y-up, source model Z-up. Sample profile data is deliberately editable.

## Next work / acceptance gates
1. Build typed schemas and resolved layout IR; no implicit grammar defaults without diagnostics.
2. Resolve exact geometry and vertical datum with stage 03; add arbitrary footprint surface clipping, floor constraints, part occlusion, narrow wall fallbacks.
3. Add true module interfaces (asset nominal dimensions, anchors, local axes, fit limits, collision envelope, LOD variants, material slots). Create assets via scripted Blender or geometry code in research 05.
4. Build actual regional series profiles from reference measurements and evidence. Produce contact sheets across seeds and sizes, check ground and aerial cameras, compare to real references. Evaluate relative proportions and style rather than claiming exact building match.
5. Test invariants: seed order and parallelism, repeatable outputs, LOD consistency, no invalid aperture rectangles, no neighbor/corner clashes, preserved semantic floor and part geometry, blank walls appropriate, valid mesh and UV, no unnecessary duplicated assets. Enforce element count limits and timeouts. Log every fallback.
6. Test performance with native UNIGINE adapter; prioritize instancing + shared materials, avoid one object per window; compare detailed and shader/baked representations.
