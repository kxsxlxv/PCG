# Research 09 — UNIGINE 2.22 SDK integration

Date: 2026-11-25 | PCG | target UNIGINE 2.22 C++ | one RTX 5070 Ti workstation
Status: version-targeted documentation/source API audit and executed independent coordinate experiment. Native SDK, headers and engine binaries are absent in this environment; no compile, render, native import, GPU, shader or engine benchmark was executed. SDK public Markdown main branch is a moving reference, not the actual local 2.22 headers. Confirm build ID/edition/precision/compiler before implementation. Do not redistribute SDK proprietary files. No Sandworm calls, no training, no runtime inference.

## 1. Integration decision
Separate engine-independent compiler (GIS, geometry, grammar, asset/material factory) from a thin C++ native resource packer and C++ runtime. Compile offline, create engine-native assets using installed SDK/official importer, load precompiled resources in flight. No reverse engineering of MESH binary or private renderer ABI. Do not introduce a custom renderer. ObjectMeshStatic for unique spatial batches, ObjectMeshCluster for repeated components, explicit tile/HLOD controller for global spatial residency. Keep glTF/GLB for interchange/debug, not repeated in-flight parse. Use a standalone PCG test world first, then integrate with host simulator via AppWorldLogic or one manager component; don't attach logic to every house or window. Editor plugin optional later, not required for first generation or deployment.

Recommended build: SDK Browser-generated C++ project with double precision enabled, CMake/toolchain matching installed engine. Host project may already be fixed to float; in that case build separate experiment and evaluate relative origin strategy instead of linking incompatible ABI. Do not mix float/double libraries, Debug/Release, SDK patch versions or incompatible CRTs. Keep source paths, compiler, SDK build, API backend, plugin list and shader schema in reproducibility manifest. Double world transforms and bounds, float tile-local mesh vertices and instance transforms, meters. SDK edition and plugin availability are unknown; validate locally. Native packer may require running engine context and licensed tools; "offline" means outside flight simulation, not necessarily a display-less engine. Do not assume headless mode or auto-import CLI flags without testing.

## 3. Native resource packer
Input canonical mesh groups (positions, normals, UV0/optional UV1, colors/semantic data, indices, material slot, semantic IDs, local bounds). Validate finite data, positive triangles, index range, correct winding, matching attribute counts, seams and LOD envelope. Use float local coordinates, stable named surfaces (role/material/pass groups). Mesh::create() -> addSurface(name) -> addVertex, addNormal, addTexCoord0, optional addTexCoord1/addColor -> addIndex -> createTangents -> createBounds -> save(path). Save returns success flag. Documented Mesh supports coordinate and triangle indices separately; addIndex appends both, so use split vertices for simple one-index-per-attribute path, inspect c/t vertex behavior after save/reload. Do not blindly recreate indices or normals after semantic hard edges. Engine tangent representation is quaternion; do not copy glTF vec4 tangent directly as if identical semantics. Test importer conversion or createTangents with mirrored UV/asymmetric normal map. Native mesh may compress attributes/vertices; verify precision, normals, colors and UV with asymmetric fixtures. Check sizes and hashes after reload; note native serialization may contain metadata, so semantic reproducibility more important than byte identity unless verified.

Save native meshes directly using SDK for bulk unique geometry. For complex authored modules use documented [Import System / importing models directly to memory](https://developer.unigine.com/en/docs/latest/code/usage/custom_import_processor/), official glTF/FBX importer and asset workflow. Standard assets can create .meta and .runtimes; native assets can be used directly if marked unchanged. Do not write .meta or GUID registry formats by guessing. Packer runs from isolated engine data directory; use unique stable paths, verify texture/material GUID/path resolution and deployment of native dependencies. Test rebuild/version migration. Export resource manifest including SDK build + precision + settings + compiler revision, content hashes, surface→role map, resource dependencies, bounds, triangles, memory estimates. Native format compatibility across SDK patches not guaranteed.

### ObjectMeshStatic vs procedural modes
Preferred production: pre-generated immutable .mesh on disk, ObjectMeshStatic::create(path), shared material references and spatial bounds; let engine stream resource data. Procedural modes only for special dynamic/rebuild cases:
- DYNAMIC retains data and needs explicit cleanup, designed for limited live meshes. Not entire city.
- FILE backs runtime procedural data by temporary files, allowing RAM/VRAM streaming.
- BLOB stores procedural source in memory, trades RAM against disk I/O.
Documented applyMoveMeshProceduralAsync and runGenerateMeshProceduralAsync are called on main thread. Move method swaps mesh data, caller must not assume input remains intact. Generation callback is on dedicated background thread, not a general parallel worker pool. Test actual lifetime/cancellation and bounds before using. Immutable production data avoids repeated procedural generation in flight.

### ObjectMeshCluster
create(asset_path), addMeshTransform() returns index, setMeshTransform(index, Math::mat4 local transform). Root world transform uses Math::Mat4/Vec3 precision type; instance transforms relative and float. One group only identical meshes with matching materials. Set per-instance values once during bounded activation, not every frame for whole city. Profile group count and draw calls by pass; no guaranteed 1 draw call. Validate transforms, scale, LOD, collisions and picking; don't rely on transient instance index as stable building identity. Store persistent asset placement IDs and mapping. Never use random scattering MeshClutter for exact building layouts.

## 4. Critical resolution of stage 06 uncertainty: actual material pass parameters
The [Current Surface Parameters node](https://github.com/unigine-engine/ai-docs/blob/main/ai_docs/md_docs/content/materials/graph/node_library/input/current_surface_parameters.md) explicitly uses current draw-call ID, not the completed screen buffer. Documentation states it can read the current surface during its own rendering pass even while ID buffers are being filled. This resolves feasibility at documentation level; no shader compiled or visual test done. For post effects use scene-buffer parameters, not current surface. Thus per-instance color/tint/roof-material variants with MeshCluster + shared materials are a strong MVP option, subject to actual shader compile, draw counts and overhead.

Declare a compact stable global surface schema in editor or via Render::getSurfaceParameters() / CustomParameterLayout::addParameterUInt/Float/Int; material schema separately Materials::getMaterialParameters(). Schema edit can trigger full shader/material reload; declare at project setup, not per tile. Layout fields are scalar float/int/uint, structure padded to 16-byte stride; use getStructureSize for actual size. Initial candidate: pcg_variant (uint; discrete palette or motif index), pcg_seed (uint), pcg_wear (float), pcg_flags (uint). Consider compact bit encoding only if documented shader integer handling and precision verified. Avoid 64-bit stable IDs in runtime parameters unless split fields really needed. IDs from renderer are frame/view or load lifetime scoped, never persistence keys. MeshClutter cannot set per-instance custom parameters. Use Material Graph Current Surface Parameters -> palette lookup / Texture 2D Array layer selection / wear modulation. UUSL alternative using documented draw-call ID and common.h getters; do not assume screen-buffer sample is safe during geometry pass. [UUSL custom parameters](https://github.com/unigine-engine/ai-docs/blob/main/ai_docs/md_docs/code/uusl/custom_parameters.md). Guard optional schema definitions and profile graph-generated shader cost.
Important distinction: custom parameters are per surface (or per instance per surface), not per individual house inside one merged surface. For merged unique geometry use per-vertex/triangle-consistent attributes or bounded material/surface groups. Test UV1 and vertex color channel quantization, interpolation and preservation across MESH save/import. Never interpolate discrete layer IDs across shared vertices of different material roles; duplicate boundary vertices or use flat/constant mechanism verified in target shader. Do not pass individual ID as float if precision risk. If UV1 used for metadata, don't conflict with lightmap/bake UV. Fallback: shared bounded palette material groups, no unique material per house. Global material parameters for genuinely shared substance data.

## 5. Texture arrays and native materials
Documented Image::create2DArray(width,height,layers,format,mips...), copy(src,layer), Image::save; Texture::create2DArray and create(image,flags,skip_mipmaps,format); setImage2D requires matched layer and mip counts when applicable. Build arrays offline, all layers same format/resolution/mip policy. Test native save format supported by array images (e.g. DDS or native texture via official workflow); do not assume PNG stores arrays. Use imported assets for persistence and material file references. Verify compression support on target renderer, actual allocation, array layer limits and mip streaming behavior. If array import fails, use multiple small material banks or atlas with per-mip padding. No dynamic upload of entire PBR library per tile. Distinguish color sRGB from data linear; compare target mesh_base shading texture packing against canonical ORM. Use tiny 2-layer solid red/green and asymmetric normal/roughness test to catch swapped layer, channel or axes. Use graph first, UUSL only for necessary custom logic (interior mapping, advanced masks). Keep source material graph files, compiled cache derived artifacts and stable versioned layout. Precompile/warm representative material permutations before flying; do not force compilation in flight. Engine-specific shader build flags and material file serialization must be tested locally. Record shader compile errors and actual pass coverage (opaque, depth, shadows, reflections, additional sensor views only if required).

## 6. Georeferencing and terrain WITHOUT Sandworm
[Georeferencing in UNIGINE](https://developer.unigine.com/en/docs/latest/principles/georeferencing/) explicitly valid for SDK 2.22. Geodetics Converter supports projection/world and geodetic/world transforms, and expects latitude, longitude, altitude in geodetic dvec3, whereas pyproj always_xy expects longitude, latitude. Built-in auto mode discovers terrain/pivot; documentation references Sandworm metadata for projected terrain. No Sandworm dependency needed in PCG: explicit WorldFrame manifest is authoritative. Do not rely on hidden Sandworm tags or recreate proprietary generated metadata. Use PROJ/pyproj offline and the same transform for both terrain and buildings. For flat Adler pilot EPSG:32637, x=easting-E0, y=northing-N0, z=height-H0 in chosen vertical datum, plus explicit asset axes and world transform. UTM grid north is not necessarily true north (orientation must be handled consistently for heading, sun/navigation, textures); PROJ convergence/scale check when integrating host. Terrain and buildings must share the same processed DTM, sampling method, horizontal projection and vertical reference; DSM includes roofs/vegetation, do not use as ground without filtering. Orthometric vs ellipsoid conversion h=H+N via verified grids; record source, datum and offsets, never silently combine. Use double origins/transforms, float tile-local vertices. Document geoid grid availability and accuracy; no vertical grid conversion performed here.

[Working with Landscape Terrain via Code](https://developer.unigine.com/en/docs/latest/code/usage/landscape_terrain/index?lang=en), version footer 2.22, documents creation from arbitrary height/albedo maps: LandscapeMapFileCreator creates .lmap, LandscapeMapFileSettings configures blend/opacity, ObjectLandscapeTerrain plus LandscapeLayerMap consumes it. Thus terrain import need not use Sandworm. User's original task is buildings; if host terrain already exists, integrate its agreed WorldFrame instead of rebuilding terrain. For stand-alone test create small synthetic layer map and then own licensed terrain; test pixel center vs grid vertex, extent, height scaling, nodata, raster orientation and bilinear sample. Terrain generation outside PCG buildings core, optional adapter. LandscapeFetch::fetchAsync, isAsyncCompleted, getHeight can verify placed structures against active terrain; fetchForce for small offline smoke tests only. Verify result/validity, requested position, time and precision, don't use stale or missing sample. Do not call synchronous fetch for every building per frame. Foundations computed offline from same final terrain. Runtime fetch only for QA or sparse exception; avoid moving already compiled geometry without tracking revision.
Landscape Terrain is flat in this georeferencing configuration; Geodetic Pivot documented for Terrain Global, not Landscape Terrain. A flat UTM scene and ECEF-derived curved ENU heights are not interchangeable. For global curved Earth scenario choose Terrain Global/geodetic adapter only after confirming host setup and edition/API; avoid introducing curvature only to buildings. A direct PROJ transform is baseline independent of Geodetics Plugin. Optional host converter test compare coordinate roundtrip and reference anchors after initialize; if auto init expects metadata not present, retain explicit WorldFrame rather than Sandworm dependency.

glTF axis transform example: (x,y,z) -> (x,-z,y), a proper +90° rotation around X, maps +Y up to +Z up. glTF asset +Z outward becomes engine -Y, so placement uses explicit mount frame, not assumption of +Y outward. Transform normals and tangent basis, preserve winding for det +1. When official importer already converts axes, do NOT convert twice; use asymmetric test with labeled axes. Mesh::flipYZ documents matching map but must validate tangent handling. UV image flip separate from world axes.

## 8. Async loading and lifetime
Use engine-native resource streaming, not competing GPU uploader. PCG scheduler chooses tiles, submits bounded requests and maintains coverage. Documented AsyncQueue::loadMesh(path,group,weight) returns operation ID; checkMesh(id) indicates queued OR loaded, NOT readiness. takeMesh consumes loaded CPU resource; inspect proper readiness/result methods and error handling in installed headers, never assume checkMesh==1 means uploaded. loadNode/takeNode hierarchy loading requires main-thread updateEnabled after load according to docs; don't expose partial node hierarchy or rely on worker-side scene mutation. For precompiled path-based ObjectMeshStatic prefer getMeshAsyncVRAM / getMeshDynamicVRAM on main thread, getMeshCurrentVRAM as one part of readiness, not guaranteed textures/shader-ready. DynamicVRAM can force-load if async mode off. Test whether disabled nodes can be prefetched and whether references pin resources; separate loaded mesh, textures, shader variants, visibility and actual first correct frame. No polling loops that block main thread. Never infer readiness from file read alone.
State machine 08 with generation token and cancel/backoff. Read/index/decompress CPU tasks outside scene thread; all node creation, transforms, material assignments, scene activation/deactivation and documented GPU requests in main thread. Queue worker outputs immutable; use bounded bytes/tasks, reserve memory before request. Late callback with stale generation must discard result. AppWorldLogic init/update/shutdown: initialize shared materials and world index; update camera/requests with frame budget; shutdown stop accepting, cancel or drain callbacks, release references and nodes on appropriate thread before world change. Don't call deleteForce from background thread. Explicit coverage parent→child atomic switch after readiness, fallback parent retained. Test cache retention, error, cancel, rapid teleport and world reload repeatedly. Engine resource caching may delay actual release; distinguish node removal vs freed VRAM. Test native API flags in release build, no assumptions about fence semantics.

## 9. Collisions, picking and data ownership
Render mesh, intersection mesh and physics collision proxy have different requirements. Surface setIntersection(bool,surface) and setCollision(bool,surface), mask controls documented on Object. Intersection flag for picking/sensor queries; physics needs actual supported collision setup and masks, don't assume flag creates a rigid body. Use simple solid proxy near relevant flight/ground collision range, not every window or full far HLOD. Preserve building identity in spatial index and mesh-sidecar ranges if native surface picking cannot identify merged building; ray hit to local 2D footprint/part and semantic ID, resolve ambiguous geometry explicitly. GPU Surface ID is ephemeral. Keep render/collision/query coverage independently measured, don't make visibility drive collision availability. Test aircraft/ground ray and physics at tile boundaries, elevated passages, roofs, multi-part structures; avoid double proxies during HLOD swap.
